# AR — Laravel Autoresponder (package context)

Read this file before changing anything under `/AR`. It is the **canonical AI context** for this library so you do not need to grep the whole tree.

## What this is

- **Composer package:** `colorrage/laravel-autoresponder`
- **PHP namespace:** `colorrage\Autoresponder`
- **Purpose:** Standalone Laravel library for **drip autoresponders**, **broadcast campaigns**, **mailer lists**, **HTML email templates**, **open/click tracking**, and **global unsubscribes**.
- **Not included:** Filament UI, admin panels, or app-specific user models. The host app configures a **subscriber** Eloquent model.

**Source of truth for behavior:** [`config/autoresponder.php`](config/autoresponder.php) (not only README — README may drift).

## Subscriber abstraction (critical)

- Any subscriber model must implement **`CmrManagement\Autoresponder\Contracts\Subscribable`** (`getSubscribableId`, `getSubscribableEmail`, `getSubscribableName`, `getSubscribableLocale`).
- Optional trait **`HasSubscriptions`** wires relationships to package models using **`subscriber_columns.key`** (default `id`).
- **`subscriber_model`** and **`subscriber_columns`** in config map PK/email/name/locale columns for non-standard tables (e.g. legacy `id_c` in a host app).

Do **not** hardcode `User` or `Client` inside package services except as **defaults in config** — resolve via `config('autoresponder.subscriber_model')`.

## Database tables (prefix default `ar_`)

Logical names (prefix + name):

- `templates`, `campaigns`, `send_logs`, `unsubscribes`
- `mailer_lists`, `list_subscribers`, `list_filters`, `list_usages`
- `sequences`, `steps`, `enrollments`, `step_logs`

**`send_logs`** is the unified row for both campaign sends and autoresponder steps (`campaign_id` nullable, `autoresponder_id` / `autoresponder_step_id` for sequences). Tracking pixel and click URLs reference **`send_logs.id`**.

**`enrollments`** drive the state machine: `state`, `next_run_at`, `dedupe_key`, `processing_token` / `processing_started_at` (atomic claiming in `ProcessEnrollments` command).

## Helper functions (`src/helpers.php`)

Use these in package code instead of duplicating prefix logic:

- **`ar_table('sequences')`** → `config('autoresponder.table_prefix') . 'sequences'`
- **`ar_log()`** → `Log::channel(log_channel)` or default logger
- **`ar_queue()`** → queue name string for jobs (default `emails`)
- **`ar_subscriber_model()`** / **`ar_subscriber_key()`** → config helpers

Models call `ar_table()` inside `getTable()`.

## Runtime flow (mental model)

1. **Enrollment:** `AutoresponderService::enroll($triggerType, Subscribable, $data)` finds active **`sequences`** matching trigger + **`default_locale`**, then **`enrollInSequence`** (dedupe, unsubscribe, optional entry filter, first step scheduling).
2. **Processing:** Scheduler/cron runs **`autoresponder:process-enrollments`** → claims rows → dispatches **`ProcessEnrollment`** job → may dispatch **`SendStepEmail`**.
3. **Sending:** **`SendStepEmail`** builds HTML via **`TokenService`**, creates **`SendLog`**, injects tracking routes, sends **`AutoresponderMail`**, writes **`StepLog`**, advances **`Enrollment`**, schedules next step.
4. **Tracking:** GET named routes **`autoresponder.track.open`** / **`autoresponder.track.click`** update **`SendLog`**.
5. **Unsubscribe:** POST/GET **`autoresponder.unsubscribe`** creates **`Unsubscribe`** and can exit enrollments.

## Routes (named — use these in mail/jobs)

- `autoresponder.track.open` — `GET .../track/open/{id}`
- `autoresponder.track.click` — `GET .../track/click/{id}/{url}` (`url` may contain slashes; route uses `where`)
- `autoresponder.unsubscribe` — `GET .../unsubscribe/{token}`
- `autoresponder.unsubscribe.process` — `POST .../unsubscribe/{token}`

Prefix defaults to `autoresponder` (see `route_prefix`).

## Extension points (host app)

- **Custom step conditions:** implement `ConditionChecker`, register in `conditions` keyed by `steps.condition_type`.
- **Stop sequence on event:** implement `StopEventChecker`, register in `stop_events`.
- **Time-based enrollment batches:** implement `TriggerHandler::getSubscribers(Sequence)`, register in `trigger_handlers`.
- **Custom merge fields:** implement `TokenResolver` (or extend `TokenService` patterns) and set `custom_token_resolver`.
- **Events:** dispatch package events from the host app; **`TriggerListener`** calls `enroll()` — ensure queue worker processes the **`autoresponder.queue`** connection/name.

## Coding rules for this repo

1. **No host app models** inside `src/` except via `config()` and contracts.
2. **Table names:** always `ar_table('name')` in models; migrations must use the same prefix pattern.
3. **Logging:** prefer `ar_log()` in package code.
4. **Jobs:** call `$this->onQueue(ar_queue())` in constructors where applicable.
5. **Keep changes focused:** this package is meant to be published; avoid coupling to CMR/Laravel app paths.

## When the parent monorepo is CMR

The **`laravel/`** app has its **own** older autoresponder implementation (Filament, `Client`, shared DB). **`/AR`** is a **clean-room package** for reuse elsewhere. Do not assume AR migrations or table names match the live CMR schema without an explicit integration layer.
